## 0. 판정

**조건부 동의 (CONDITIONAL AGREE).**

방향에는 동의한다. 영어 전용 생성 계약을 따로 두고, 저장처(`ExamAnalysisExtension`, `agentType='commentary'`)와 V3 렌더·이미지 복사 흐름은 재사용하며, 수치는 코드 집계가 결정하고, 근거 없는 등급컷·정답률·변형률은 금지한다는 원칙 모두 맞다.

다만 지금 초안은 **"무엇을 하겠다"는 서술 수준**이고, 실패 처리·근거 검증·무효화 규칙이 **프롬프트 지시로만 막히는지, 코드로 강제되는지**가 정해져 있지 않다. 이 코드베이스는 같은 유형의 사고를 여러 번 겪었다(§12-10 조용한 강등, §12-11 항등식 가드, §12-12 블랙리스트 유출). 아래 **B1~B8**이 계획에 명시적으로 들어가면 동의로 전환한다. 하나라도 빠지면 Round 2에서 반대한다.

## 2. 초안에 없는 추가 발견 (코드 근거)

**F1. 실패하면 이전 성공본을 덮어쓰고, 화면은 성공처럼 보인다.**
- 실패를 성공으로 바꾸는 경로가 세 개다. ① `BaseAgent.run`이 AI 실패 시 `ruleBased()`(수학 중심의 일반 문구)를 돌려준다(`base-agent.ts:86-95`, `commentary-agent.ts:1777`). ② V3 확장이 실패해도 base만으로 반환된다. ③ `extractJson`이 잘린 JSON을 부분 복구해 정상 결과로 취급한다(`:1698-1732`).
- 예외가 나면 orchestrator가 `result: {}`로 덮어쓴다(`orchestrator.ts:163-165, 256-258`). 이 시점에 이전 성공 총평은 사라진다.
- UI는 commentary의 `errorMessage`를 읽지 않는다(`english/AnalysisDetail.tsx:290-291`). `{}`도 총평이 있는 것으로 취급한다.
- 목록 배지는 행이 있기만 하면 '총평완료'다(`ExamPaperList.tsx:127`). 목록 API는 `errorMessage`를 select하지도 않는다(`api/exam-analysis/route.ts:58-65`).

**F2. 성공 토스트가 거짓일 수 있다.** analyze-extended는 에이전트가 실패해도 200과 `[{status:'failed'}]`를 반환한다. 그런데 클라이언트는 `res.ok`만 보고 '총평이 생성되었습니다'를 띄운다(`english/AnalysisDetail.tsx:346-352`). 수학 자동 체인도 같다(`page.tsx:308`).

**F3. 재생성 후에도 이전 `v4_*` 필드가 다시 살아난다(수학에도 있는 버그).** `parseV3Response`는 비교 데이터가 없으면 `v4_previous_comparison: undefined`를 반환한다(`:1260`). JSON 직렬화를 거치면 이 키가 사라지고, orchestrator는 "새 결과에 없는 v4_* 키"를 **이전 결과에서 복원**한다(`orchestrator.ts:145, 238`). 결과적으로 비교 토글을 끄고 재생성해도 **예전 비교 문단이 남는다.** 영어 결과도 이 병합 경로를 그대로 지나가면 같은 오염을 겪는다.

**F4. 재분석은 총평을 조용히 지운다.** `analyze/route.ts:235`가 `examAnalysis.deleteMany`를 실행하고, 스키마는 `onDelete: Cascade`다(`schema.prisma:574`). 수학은 `hadCommentary`일 때 자동으로 재생성하지만, 영어는 체인에서 빠져 있어(`page.tsx:387`) 재분석하면 **총평이 아무 안내 없이 사라진다.**

**F5. 메타데이터 캐시는 교정을 반영하지 않는다.** `generate-metadata`는 같은 analysisId에 `isReady`가 있으면 계속 그 값을 재사용한다(`route.ts:58`). orchestrator는 이 값을 base로 주입한다(`orchestrator.ts:195`). 교사가 PATCH로 배점이나 근거를 고쳐도 base(`overall_comment`, `notable_questions`)는 교정 전 데이터로 남는다. 초안이 말하는 '입력 서명'은 이 경로까지 포함해야 한다.

**F6. 주변 학교 비교 블록이 수학 전용이다.** 비교 블록의 `TYPE_LABELS`에는 수학 키만 있다(`commentary-agent.ts:1008-1012`). 그래서 영어 인근 시험의 유형 분포는 `grammar 5문항`처럼 **소문자 영문 키 그대로** 프롬프트에 들어간다. `stripEnglishEnums`는 대문자만, 대소문자 구분으로 매칭하므로(`:92-100`) 출력에서도 걸러지지 않는다. 내용 면에서도 문제가 있다. 영어 내신은 학교마다 교과서 출판사와 부교재가 달라서, **학교 간 '단원' 비교는 의미가 없다.** AI 추정 난도로 학교 간 Level을 비교하는 것도 근거가 약하다.

**F7. 새 영어 분류 키는 기존 enum 방어로 막을 수 없다.** `SUBTYPE`/`SOURCE`/`THINKING`/`TRANSFORMATION` 키는 소문자 snake_case(`grammar_error`, `main_idea`)이거나 **일반 영어 단어**(`detail`, `summary`, `blank`, `mock`, `new`, `apply`)다. 일반 단어를 출력 단계에서 치환하면 실제 영어 인용문이 깨진다. 따라서 ① 입력 단계에서 한글 라벨만 전달하고, ② 영어 인용을 **구조적으로 분리**하는 방식만 가능하다(B5).

**F8. V3 평균 난이도가 화면 공식과 다르다(§12-4 재발).** `buildV3UserPrompt`는 문항 수 단순평균을 쓴다(`:1553-1556`). 화면은 `weightedAverageDifficulty`를 쓴다. 영어 경로는 반드시 공용 헬퍼를 쓰고, 값에 'AI 추정' 기준을 붙여야 한다.

**F9. 수식 정규화가 영어 본문에도 적용된다.** `deepNormalizeMath`(`base-agent.ts:19`)가 모든 문자열에 적용되므로, 영어 지문 속 `$5` 같은 표기가 수식 쌍으로 잘못 인식될 수 있다. 영어 인용 필드는 수식 정규화에서 제외하거나 `$`를 이스케이프해야 한다.

**F10. 난도 기반 지표가 측정값처럼 보인다.** KPI의 '킬러 비중'과 변별력 차트 공식(`chart-image-generator.ts:786`)은 응답 데이터 없이 난이도와 배점만으로 계산한 값이다. 지금 영어 화면은 `v3Charts`를 넘기지 않아(`english/AnalysisDetail.tsx:1154-1189`) 변별력 차트가 나오지 않는다. **이 상태를 유지해야 한다.** KPI는 'AI 추정 고난도'로 표기를 바꿔야 한다.

## 3. 블로킹 이슈 — 합의 조건

### B1. 실패·저장 의미론을 '전부 성공하거나 아무것도 저장하지 않음'으로 정의 (F1, F2)
- 영어 경로에서는 `ruleBased` 폴백, 부분 JSON 복구, 'base만 저장'을 **모두 금지**한다. 출력이 잘리면 실패로 처리한다.
- 실패하면 **`result`를 건드리지 않는다.** `errorMessage`와 `_meta.lastFailure{at, reason(사용자용 범주)}`만 갱신한다.
- UI는 이전 성공본을 그대로 보여 주고 '최근 재생성 실패 — 이전 총평 표시 중' 배너를 띄운다.
- 토스트는 응답 배열의 `status`로 판정한다.
- 목록 배지는 `result`가 유효 계약을 통과했고 `errorMessage`가 없을 때만 '총평완료'로 표시한다. 이를 위해 목록 API select에 필요한 최소 필드를 추가한다.
- 토스트·배지 수정은 수학에도 적용한다(같은 버그다). 결과 보존 규칙은 영어 계약에 먼저 적용하고, 수학은 후속 과제로 기록한다(수학 동작 보존 원칙).

### B2. 근거 검증은 프롬프트가 아니라 **코드 검증기**로 강제
`validateEnglishCommentary(ctx, draft)`는 순수 함수로 만들고 오류 목록을 반환한다. 최소 검사 항목:
1. **문항 참조 실재성** — 모든 `refs`/`question_number`가 입력 문항 번호와 문자열로 정확히 일치해야 한다(예: `"서술형2"`).
2. **수치 허용 목록** — 영어 인용을 제외한 한국어 본문에서 숫자를 모두 추출한다. 각 숫자는 코드가 만든 허용 집합(문항번호, 문항수, 배점, 비율, 지문 수, 실측 지표가 있으면 그 값)에 있어야 한다. 비율은 반드시 분모가 표시된 형태로만 허용한다.
3. **문항 사실은 데이터가 렌더한다** — 대표 문항의 형식·세부유형·배점·출처 확인 상태·난도 기준 라벨은 AI가 쓰지 않는다. 코드가 `questions[]`에서 그린다. 삼보 사례(객관식을 '서술형'으로 표기)는 이 방식이면 구조적으로 생길 수 없다. 기존 `reconcileDifficultyRows` 패턴과 같다.
4. **금지 주장 검사** — 등급컷, 평균, 정답률, 오답률, 변별도·변별력 수치, 적중, 변형률, '다음 시험에 나온다', '전국 표준', 그리고 학생 실력 단정('아이가 ~를 어려워')을 잡는다. 단, `examStats`나 `observation`이 실제로 있을 때만 그 항목을 허용한다.
5. **출처 주장 게이트** — '교과서 본문 그대로', '외부 지문' 같은 출처·변형 서술은 `verification ≠ unverified` 또는 `transformation_evidence`가 있는 문항을 참조할 때만 허용한다.
6. **섹션 존재 규칙** — 서술형이 0이면 서술형 섹션을 금지한다. 듣기 문항이 없으면 듣기 언급을 금지한다. 비교 데이터가 없으면 비교 섹션은 `null`이어야 한다.
7. **표기 검사** — 영어 인용 밖에서는 snake_case 키, 대문자 enum, raw `$`, HTML 태그, 모델·벤더명을 금지한다.
8. **인용 실재성·길이** — 산출물의 영어 문구(라틴 3단어 이상)가 저장된 근거 텍스트 묶음의 부분 문자열인지, 개수·길이가 B5 기준 안인지 검사한다. 원문을 본 것처럼 쓰는 표현('본문에서는 …라고 했다', '지문 그대로 출제')은 출처·변형 근거(B2-5)가 없으면 금지한다.

위반이 나오면 **보완 요청 1회**를 한다(초안 그대로 + 오류 목록만 전달). 그래도 실패하면 B1의 실패 처리로 넘어간다.

### B3. 입력 서명과 무효화 규칙을 데이터로 정의 (F4, F5)
- `englishCommentarySignature(ctx)`는 순수 함수다. 서버(저장)와 클라이언트(비교)가 **같은 함수**를 import한다(§12-4).
- 정규화한 입력을 안정 정렬한 JSON의 FNV-1a 해시면 충분하다.
- 서명 대상: 문항별 `question_number`·형식·배점·난이도·`question_type`·`ability_domain`·topic·정규화한 `english_analysis`, `key_vocab`/`key_structures`(인용 근거 묶음이므로), `totalPoints`, 시험 맥락(학교·학년·회차·범위), `examStats`, 사용한 학습 대책 팩 버전, 계약 버전. (v1.1에서 비교를 켜면 비교 대상 ID 목록과 토글을 추가한다.)
- `ai_comment`는 서명에서 **제외**한다. 표시용 문장이 바뀌는 것은 총평의 근거 변경이 아니다.
- 영어 경로는 `'metadata'` extension을 **사용하지 않는다.** base를 따로 만들지 않는 단일 계약이다(아래 아키텍처 참조).
- 재분석(F4) 정책을 명시한다. 기존 총평이 있으면 재분석 확인 단계에서 '총평이 함께 다시 만들어집니다'라고 안내한다. 그 뒤 학습 대책 준비 → 총평 순서로 체인을 실행한다. 이 규칙은 `hadCommentary` 또는 자동 옵션일 때 수학과 같다.

### B4. 계약은 분리하고 렌더러는 갈라지지 않게 — 프로젝션 방식
- 저장 형태: `result = { ...V3 호환 필드, english: EnglishCommentaryV1, _meta: { contract: 'english-v1', promptVersion, inputSignature, coverageTier, generatedAt } }`.
- `english` 객체가 원천(SoT)이다. V3 호환 필드는 순수 함수 `projectEnglishToV3(english, ctx)`가 저장 시점에 만든다.
- 프로젝션은 자신이 만들지 않는 V3/`v4_*` 키를 **명시적으로 `null`로 쓴다**(F3 오염 차단).
- 영어 계약 결과에는 orchestrator의 v4 병합을 **적용하지 않는다.**
- 문항 단위 사실(번호·형식·배점·세부유형·출처 상태)은 기존 행 재구성처럼 렌더 시점에 현재 `questions`에서 다시 만든다. 그래야 교정 결과가 즉시 반영되고, 산문만 B3의 '이전 근거' 배너로 관리된다.

### B5. 영어 인용 — 저장된 근거 안에서만 허용 + 저작권·조판 정책
- **전제(코드로 확인함):** 저장된 문항(`AnalyzedQuestion`)에는 지문·발문·선지의 원문 텍스트가 없다. 영어 원문은 `english_analysis`의 자유 텍스트(`distractors`, `writing_conditions`, `accepted_answers`, `skills`)와 `key_vocab`/`key_structures`(`types.ts:52-54`), `ai_comment`에만 단편적으로 있다. 즉 총평 단계의 AI는 **원문을 본 적이 없다.** 그런데도 영어 문장을 '인용'하면 그것은 **원문 대조를 가장한 지어낸 문장**이다.
- 그래서 규칙은 이렇다. **v1 산출물에 들어가는 영어 문구(라틴 문자 3단어 이상 연속)는 저장된 근거 텍스트 묶음의 부분 문자열이어야 한다.** 묶음 = 위 필드들을 공백 정규화한 것. 검증기가 문자열 포함 여부로 강제한다(B2-8). 이 묶음에 없는 영어 문장을 지문 인용처럼 제시하면 실패다. 예문을 지어내 '이런 식으로 나왔다'고 쓰는 것도 금지한다.
- 인용은 별도 구조 필드(`quote: { en, from_field, ref }`)에만 넣고, 한국어 산문 안에는 넣지 않는다. 산문 속 1~2단어 영어 표기(예: `despite`, `keep A from -ing`)도 `key_vocab`·`key_structures`·`skills`에 있는 것만 허용한다.
- 저장된 단편도 공개 블로그로 나가므로 **보고서 전체 인용은 최대 3개, 각 20단어 이하**로 제한한다. 서술형 모범답안 전문은 게재하지 않는다. `accepted_answers`는 `scoring_source`가 있을 때 '조건 요약'으로만 쓴다.
- 렌더링 규칙:
  - `lang="en"` 요소로 감싸고, 단어 중간에서 줄이 끊기지 않게 한다(`overflow-wrap: break-word`, `hyphens: manual`).
  - 인용 필드는 수식 정규화와 enum 치환에서 제외한다(F7, F9).
  - 720px 캡처와 375px 화면 모두에서 인용 길이가 레이아웃을 깨지 않아야 한다.

### B6. 비교는 v1에서 **전부 숨김** (F6)
- 영어 v1에서는 주변 학교 비교와 같은 학교 연도 비교를 **모두 끈다.** 코디네이터 제안(동등성·출처 보장 전 초기 릴리스에서는 숨김)에 동의한다.
- 이유: 영어 내신은 학교마다 교재가 달라 단원 비교가 성립하지 않는다. AI 추정 난도로 학교 간 비교를 하는 것은 근거가 약하다. 같은 학교라도 이전 분석본이 다른 프롬프트 버전(근거 필드 유무)이면 세부유형 분포의 동등성이 보장되지 않는다. 또 현재 비교 프롬프트는 수학 라벨이라 영어 키가 그대로 샌다.
- 구현 시: 영어 경로에서는 `findNearbyExamData`를 호출하지 않는다. 비교 토글 UI(`includeNearby`/`includeYearCompare`)도 영어 화면에서 숨긴다. 프로젝션의 비교 필드는 `null`로 고정한다. 검증기는 비교 표현('작년보다', '인근 학교', '다른 학교')을 금지한다.
- **v1.1 후보:** 같은 학교·같은 학년·같은 `ENGLISH_PROMPT_VERSION` 이상 분석본끼리만, **구조 지표**를 비교한다. 대상은 형식 구성, 서술형 문항·배점, 세부유형 분포, 지문 수이며, 분모는 코드가 명시한다. 단원·Level 비교는 하지 않는다.

### B7. 접근 잠금은 합격 기준을 통과한 뒤 해제
- 잠금 해제는 UI를 서버 기준(플랜·데모)과 맞추는 것으로 한다.
- 해제는 **§6 합격 기준(골든셋)을 통과한 커밋에서만** 한다. 그 전까지는 SUPER_ADMIN 잠금을 유지한다.
- 잠금 문구 '영어 총평은 준비 중입니다'는 해제와 함께 제거한다.

### B8. 수학 무회귀를 증명으로 고정
- MATH 입력에 대한 `buildPrompt`, `buildV3UserPrompt`, `buildSystemPromptV3`, `buildSystemPromptV4` 출력이 **바이트 단위로 동일**해야 한다(`scripts/parity/` 방식, §12-13 선례).
- 수학 자동 체인(`page.tsx:300-316`)의 흐름은 바뀌지 않아야 한다. 토스트·배지 수정만 예외다.
- `verify:template-blocks`에 수학 fixture를 넣어 **영어 블록이 렌더 목록에 0개**임을 확인한다(§12-14).

**배치 제안**
- `src/lib/exam-analysis/english/commentary/`에 `context.ts`, `schema.ts`(Zod), `prompt.ts`, `validate.ts`, `project-v3.ts`, `signature.ts`를 둔다.
- orchestrator에는 분기 한 곳만 추가한다(`subject===ENGLISH && agentType==='commentary'` → `runEnglishCommentary`).
- 버전 상수 `ENGLISH_COMMENTARY_VERSION`을 새로 둔다. 기존 `AGENT_PROMPT_VERSIONS.commentary`와 독립이다.
- 기존 `CommentaryAgent`의 수학 경로는 건드리지 않는다.

**근거 충분도 등급 (생성 전 코드 판정)**

'근거 있는 문항'의 정의: `subtype`이 있고, `skills`·`distractors`·`writing_conditions` 중 하나 이상이 비어 있지 않은 문항.

| 등급 | 조건 | 동작 |
|---|---|---|
| 충분 | readiness 통과 + 근거 있는 문항 ≥ 80% | 전체 계약 생성 |
| 제한 | 50~80% | 대표 문항은 근거 있는 문항 중에서만 고른다. 특징은 3개로 제한한다. '근거 제한' 표기를 붙인다 |
| 차단 | < 50% 또는 readiness 실패 | 생성하지 않는다. 문항 근거 검토로 안내 |

출처 미확인만으로는 **절대 차단하지 않는다.** 대부분의 시험이 미확인이다. 출처 미확인은 출처 관련 주장만 막는다(B2-5). 이 기준치는 골든셋 결과를 보고 한 번 조정한다.

| 섹션 | 필수 | AI 작성 | 코드 작성 | 분량 |

전체 한국어 산문은 대략 1,800~3,200자다. 헤드라인 리트머스('옆 학원도 할 수 있는 말인가')는 유지한다. 다만 '1/3 표준' 같은 외부 기준 문장은 제거한다.

**영어 교육 관점에서 프롬프트에 넣을 분석 렌즈** — 실제 근거 필드가 있는 것만 쓰도록 지시한다.
- **어법:** 판단 단위(밑줄 1개 / 여러 개 중 개수 고르기 / 모두 고르기 — 같은 문법 항목이라도 부담이 다르다), 문법 항목(`skills`), 문장 하나만 보고 판단할 수 있는지 아니면 앞뒤 문맥이 필요한지(시제·대명사 수 등).
- **어휘:** 문맥상 쓰임(반의어 바꿔치기형), 영영풀이, 어형 변화를 구분한다. '뜻 암기만으로 풀리는지'를 판단 기준으로 설명한다.
- **독해:** 사실 확인(일치·불일치)과 추론(빈칸·순서·삽입·요약·무관·지칭·함축)의 비중을 구분한다. 선지 함정은 `distractors`에 근거해 쉬운 말로 설명한다('본문 표현을 그대로 가져온 오답', '범위를 넓힌 선지' 등). 실제 학생 오답처럼 표현하지 않는다.
- **서술형:** 조건의 개수와 종류(단어 수, 주어진 단어, 어형 변화, 어순·문장 수), 본문 문장을 다시 쓰는 문항인지 새 문장을 만드는 문항인지, 부분점수·감점 서술은 `scoring_source`가 있을 때만 쓴다.
- **지문 운용:** `passage_id`로 '한 지문에 여러 문항' 구조를 드러낸다. 지문 수와 문항 수를 구분해 쓰고, 단어 수처럼 측정하지 않은 분량은 말하지 않는다.
- **학교급·시험 종류:** 중등은 교과서·의사소통 대화문 중심이고, 고등은 부교재·모의 지문·추론형·조건 영작 중심이다. 실제 있는 영역만 섹션으로 만든다. 학력평가·모의고사(MOCK)는 내신 문법(본문 암기, 학교 채점)을 쓰지 않고, 듣기가 있으면 포함한다.
- **예측과 '변별':** 응답 데이터가 없으므로 '변별력이 높다'는 쓰지 않는다. 대신 '배점이 크고 요구 사고가 높은 문항'으로 쓴다. 다음 시험 예측은 v1에서 금지한다.

**표시·내보내기**

## 6. 최소 합격 기준 (구현 완료 판정)

**A. 자동 검사 (LLM 없이, `npm run verify:en-commentary`)**

4. 등급 판정: 충분·제한·차단 경계값 fixture로 확인한다.
5. 수학 무회귀(B8): 프롬프트 바이트 동일. 기존 `verify:template-blocks`, `verify:render`, `verify:capture-sig`, `verify:claims`, `verify:llm`, `verify:en-evidence`, `verify:english`, `verify:contrast` 통과. `npx tsc --noEmit` 통과(dev 서버와 같은 `.next`에 build를 돌리지 않는다).

**B. 실패·저장 경로 (DB 포함 스크립트 또는 브라우저)**
6. 생성 실패를 주입했을 때: 이전 성공 `result`가 바이트 동일하게 유지된다. 실패 배너가 뜬다. 성공 토스트는 0회다. 목록 배지는 '총평완료'를 오표시하지 않는다.
7. 동시 실행: 수동 클릭과 자동 체인이 겹쳐도 LLM 호출은 1회다. 늦게 끝난 오래된 실행이 새 결과를 덮어쓰지 않는다.
8. 교정 → '이전 근거로 만든 총평' 배너 → 재생성 → 배너 해제. 재분석 → 안내 문구 → 체인으로 재생성.

**C. 골든셋 (실제 모델 출력)**

**D. 브라우저 (Chrome MCP 실측)**

14. 375px 폭에서 가로 스크롤이 없다. 다크 테마 대비는 실측 WCAG ≥ 4.5다(§12-15). 영어 인용이 단어 중간에서 끊기지 않는다.
15. 화면·로그 문구에 모델명·벤더명·영문 enum·raw `$`가 0건이다(규칙 #0, #0-1, §6). 사용자 노출 에러는 `toUserFacingError`를 거친다(§12-12).

## 7. 「3자 검토에서 결정할 항목」에 대한 Claude 입장

1. **최소 변경 접점:** orchestrator 분기 1곳, 프로젝션 함수, 영어 블록 2~3개로 한정한다. 수학 `CommentaryAgent`, V4, HTML 렌더러는 바꾸지 않는다. 예외는 토스트·배지 버그 수정뿐이다.
2. **엄격성 vs 실사용:** 근거 충분도 3단계(§5)로 정한다. 출처 미확인으로는 차단하지 않고, 출처 주장만 막는다. 차단 기준은 readiness 실패와 근거 있는 문항 50% 미만이다.
3. **필수 섹션·분량·재시도·합격:** §5 계약 표와 §6을 따른다. 재시도는 보완 요청 1회로 제한하고, 잘림은 재시도하지 않고 실패로 처리한다(사용자가 다시 누를 수 있음).
4. **서명·보존:** 서명은 산문에만 적용하고, 문항 사실은 렌더 시점에 다시 만든다. 실패하면 이전본을 보존한다. 재분석 시에는 총평이 삭제(cascade)됨을 안내하고, 체인으로 재생성한다.
5. **자동 생성 연동:** 기존 `mathlab_auto_commentary` 옵트인을 영어에도 적용한다. 순서는 학습 대책 → 총평으로 직렬 실행하고, 서버 in-flight dedupe를 둔다. 자동 경로의 성공 토스트도 응답 상태로 판정한다.

## 구현 시 지킬 점 (계획 수정 불필요)

1. **숫자 배제 검증기의 영어 문법 용어 오탐.** '5형식', '2형식 동사', '3인칭 단수', 'to부정사'처럼 숫자가 들어간 한국 영어교육 표준 용어가 흔하다. 산문 숫자를 일괄 거절하면 정상 해설이 계속 실패한다.
   - 문법 용어 패턴(`\d형식`, `\d인칭` 등)을 명시 예외로 둔다. 학년·학기·회차 표기도 예외다(키커는 코드가 그리므로 AI 산문에 둘 필요가 없다).
   - 문항 번호는 산문에 쓰지 않고 구조화된 참조로만 받는다고 프롬프트에 분명히 적는다. 그래야 보완 요청이 낭비되지 않는다.
   - 검증기 음성·양성 테스트 모두에 이 사례를 넣는다.
2. **lease/CAS가 이전 성공본을 가리지 않게 한다.** 진행 토큰을 같은 extension 행에 둘 때 Prisma JSON 갱신은 통째 교체다. 따라서 진행 중 상태는 `report`·`context`를 보존한 채 덧붙여야 한다. 최초 생성 중인 행이 목록에서 '총평완료'로 보이면 안 된다. CAS는 `lastRunAt` 등 스칼라 조건의 `updateMany`로 구현하면 JSON 비교를 피할 수 있다.
3. **이전 근거로 만든 보고서를 공유할 때 경고한다.** 스냅샷은 그 자체로는 일관되지만, 교정 전 숫자가 학부모에게 나갈 수 있다. 서명이 다를 때 이미지 복사를 누르면 '교정 전 기준 보고서'임을 알리는 확인을 한 번 거치게 한다. 화면 배너만으로는 복사 버튼 옆에서 놓치기 쉽다.
