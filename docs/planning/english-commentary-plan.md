# 영어 기출 총평 — 조사·3자 검토·구현 계획

작성: 2026-10-02. 상태: 조사·3자 합의·구현·검증 완료. 담당: Codex.

완료 결과: 영어 전용 총평 생성·저장·재생성, 근거 변경 안내, 테마와 이미지 공유를 구현했다. 실제 Claude와 Grok의 계획 검토 후 구현했고, 실제 생성 산출물 8건의 반복 검토에서도 세 검토자가 최종 동의했다. 순수 회귀 39건, 실제 DB 5건, 실제 HTTP 10건, 브라우저·캡처 및 프로덕션 빌드가 통과했다. 상세 결과와 합성 검증 입력·외부 편집기 확인 범위는 [검증 기록](./english-commentary-validation.md)에 있다.

## 목표와 완료 조건

영어 기출 분석에서 수학 총평처럼 교사·학부모가 바로 읽고 공유할 수 있는 완성도 높은 총평을 생성·저장·다시 열기·재생성한다. 영어 문항의 실제 근거를 설명하고 그 근거와 학습 행동을 연결한다. 사용자 요청에 따라 웹 조사 → 계획 → 실제 Claude/Grok과 3자 검토 및 수정 → 구현 및 검증 순서로 진행한다. 전체 웹의 모든 글을 전수 조사했다는 주장은 하지 않는다. 중등·고등 내신, 학원 원문, 교육청 자료, 서비스 사례를 폭넓게 비교하고 공통 패턴과 반례를 기록한다.

## 현재 코드에서 확인한 문제

- `english/AnalysisDetail.tsx`는 영어 총평을 SUPER_ADMIN만 생성하도록 잠근다. 서버 `analyze-extended`는 이미 지점 플랜/데모 권한을 검사하므로 UI와 서버 기준이 다르다.
- `CommentaryAgent`는 과목 라벨은 분기하지만 영어도 수학 중심의 V3 작성 구조를 쓴다. 영어의 `english_analysis`(세부유형·출처 검증·변형 근거·선지 함정·영작 조건·채점 출처·학습 제안)를 총평 입력에 전달하지 않는다.
- V3 프롬프트에는 검증되지 않은 '서술형 전국 표준 약 1/3' 비교가 남아 있다. 영어에서 사용하면 안 된다.
- 확장 분석 입력은 시험 학교·학년·범위 등 식별 맥락을 충분히 전달하지 않는다.
- V3 생성 실패 후 base만 반환해도 완료로 저장될 수 있다. 영어의 신규 품질 기준을 통과하지 못한 결과는 성공으로 표시하면 안 된다.
- 기존 저장처 `ExamAnalysisExtension.result` 및 `agentType=commentary`를 재사용할 수 있다. 새로운 DB 모델이 반드시 필요한 상황이 아니다.
- 문항 근거 편집/재분석으로 입력이 바뀌어도 이전 총평의 유효성을 식별하는 장치가 필요하다.
- 영어 분석 후에는 학습 대책 준비만 실행되고 총평 체인은 제외되어 있다.

## 초안 구현 설계 (아래 2차 결정으로 대체)

1. **영어 근거 컨텍스트**: 기존 `readEnglishQuestionAnalysis`, 배점/형식/난도 공통 헬퍼를 사용한다. 시험 식별 맥락, 전체 문항 집계, 출처/세부유형 분포, 문항별 근거를 전달한다. 미확인/AI 추정/교사 확인/실측을 구분한다. 학생 답안이 없으면 학생의 현재 실력을 진단하지 않는다.
2. **영어 전용 생성 계약**: 수학 프롬프트를 덧붙여 수정하기보다 영어 작성 프롬프트와 Zod 계약을 분리한다. 개요, 3~5개 근거 기반 핵심 특징, 대표 문항의 '요구 사고→함정→대비', 서답형 조건, 우선순위별 학습 행동, 조건부 비교, 학부모용 결론을 생성한다. 대표 문항 수는 실제 문항 수·근거량에 맞춰 제한한다.
3. **신뢰성 검사**: 문항 참조가 실제 존재하는지, 핵심 주장에 근거 참조가 있는지, 충분한 본문과 실행 행동이 있는지 검사한다. 수치는 코드 집계를 진실의 원천으로 삼는다. 채점 출처 없는 감점/부분점수, 원문 없는 변형 비교, 성적 없는 컷/정답률을 금지한다. 잘린/실패/빈 응답은 완성 총평으로 저장하지 않는다. 필요 시 제한된 1회 보완 요청 후 명확한 재시도 상태를 제공한다.
4. **저장·캐시**: 기존 commentary extension을 사용하며 영어 보고서 버전·입력 서명을 기록한다. 영어 신규 경로는 수학 동작을 보존한다. 재생성 실패 시 이전 성공본 보존을 검토한다. 교사 교정 후에는 이전 근거로 만든 총평임을 표시하고 명시적 재생성을 제공한다.
5. **하이파이 표시·공유**: 기존 V3의 타이포그래피·테마·블록·네이버 이미지 복사 흐름을 최대한 재사용한다. 영어 전용 구조를 기존 V3 표현 필드로 변환하거나 영어 블록을 추가해 근거와 전략이 보기 좋게 읽히게 한다. 출처·세부유형의 집계 및 대표 문항 근거를 연결한다. 화면과 복사 산출물의 내용이 일치해야 한다. 과목 라벨·버튼·모바일 폭·빈 상태·읽기 순서·다크 대비를 확인한다.
6. **접근·후속 흐름**: 수학과 동일한 실제 플랜/데모 권한으로 영어 총평을 연다. 자동 생성은 기존 opt-in 의도를 유지하고 영어 학습 대책 준비와 상태가 충돌하지 않도록 순서를 정의한다. 메타데이터·총평 중복 호출, 오래된 결과 덮어쓰기, 잘못된 성공 토스트를 방지한다.
7. **검증**: 정상/근거 부족/구형 JSON/문항 없음/서술형 없음/배점 누락/소문항/실측 유무/허위 문항번호/실패 보존/교정 후 stale/타 과목 경로를 검사한다. 기존 영어 근거/영어 taxonomy/총평 및 공유 관련 회귀 검사와 타입 검사를 실행한다. 실제 모델 출력 샘플과 브라우저에서 생성→저장→재조회 및 화면·공유 결과를 확인한다. 실행 중인 dev와 같은 `.next`에 production build를 돌리지 않는다.

## 3자 검토에서 결정할 항목

- 별도 영어 생성 경로와 기존 V3 렌더/내보내기 사이의 최소 변경 접점.
- 엄격한 근거·품질 기준과 구형/근거 부족 시험의 실사용 가능성 사이의 기준.
- 필수 섹션, 생성 분량, 재시도 비용, 실제 생성 결과의 합격 기준.
- 입력 서명 및 교사 교정 이후 재생성/기존 결과 보존 방식.
- 일회성 명시적 생성과 기존 자동 총평 옵션의 영어 연동 방식.

## 2차 수정 결정 — 구현 계약

### 독자와 근거

학부모에게 공유할 수 있는 영어 시험 해설 보고서가 주 산출물이다. 문항 요구와 준비 행동을 구체적으로 연결한다. 현재 DB에는 지문·선지 원문이 없으므로 PDF를 다시 호출하거나 원문을 본 것처럼 쓰지 않는다. 저장된 `english_analysis`, `ai_comment`, `key_vocab`, `key_structures`만 입력한다. 학습 대책 팩은 의존성에 넣지 않는다.

1. `src/lib/exam-analysis/english/commentary/`에 독립 컨텍스트·계약·검증기·프롬프트·생성/저장 서비스를 둔다. `ENGLISH_COMMENTARY_VERSION`은 수학 버전과 독립이다. `BaseAgent` 폴백, 기존 V3 프롬프트, metadata, v4 병합은 영어에서 사용하지 않는다.
2. 저장 원천은 영어 전용 객체다. `{ kind: 'english-commentary', version, inputSignature, generatedAt, context, report }`를 기존 `commentary` 행에 저장한다. 수학 호환 필드로 투사하지 않는다. `context`는 생성 당시 정규화된 시험·문항·코드 집계의 스냅샷이다. 렌더/이미지 캡처는 이 스냅샷과 같은 보고서만 쓴다. 교정 후 최신 숫자와 옛 산문을 섞지 않는다.
3. AI는 제목·덱·개요, 핵심 특징 2~5개(소형 시험은 최대 3), 대표 문항 해설, 학습 행동 최대 3개, 학부모 결론을 작성한다. 핵심 특징·대표 문항·행동은 반드시 문항 참조를 갖는다. 대표 문항 수 상한은 `min(4, max(2, ceil(문항수/8)))`, 실제 후보 수를 넘지 않는다. 근거가 전무한 구조 보고서는 대표 문항/행동을 빈 배열로 허용한다. 각 문단은 요구→그 이유→대비를 쉬운 한국어로 설명하며 일반적인 학원 홍보 문구를 쓰지 않는다.
4. 형식·세부유형·사고·배점·난도 기준·출처 검증·서술형 조건·채점 근거·응답 관측치는 코드가 기록에서 직접 표시한다. AI가 이 구조 필드를 생성하지 않는다. 집계는 대문항 기준이고 소문항 배점을 재합산하지 않는다. 미확인 배점은 미확인으로 남긴다. 난도는 추정/교사 판단 표시와 분포로 보여 주며 영어 보고서에 가중 평균·킬러 비중·변별력 차트를 사용하지 않는다.
5. `source.verification`, `transformation_evidence`, `scoring_source`, `standards_source`가 없는 관련 주장은 금지한다. 관측치는 집단·응답 수·출처와 함께 그대로 표시하고 전체 학교로 일반화하지 않는다. 지문 수는 `passage_id` 기록 범위 안에서만 제시한다. 단원명 안의 교육과정 어휘 수를 교육과정 기준처럼 인용하지 않는다.
6. v1에서는 주변 학교와 과거 시험 비교를 모두 숨긴다. 비교 요청·수집·토글·본문을 만들지 않는다. 수학 비교에는 영향이 없다.

### 품질 계약과 읽기 안전성

- Zod로 생성 응답뿐 아니라 저장 JSON의 외부 경계를 검증한다. 구형 영어 총평은 새 보고서로 오인하지 않고 재생성 안내로 표시한다. 배열·객체·null 등 손상된 JSON도 렌더 예외를 내지 않는다.
- readiness(독립 선언 문항/배점·누락·단원) 실패는 서버와 UI 모두 차단한다. 추가로 중복 문항번호·소문항 배점 초과를 차단한다. 출처 미확인/세부 근거 부족만으로는 차단하지 않는다. 근거 범위는 `구조 중심 / 문항 근거 포함 / 교사 확인 포함`으로 표시한다. 구조 중심 보고서도 검증된 구성을 해설할 수 있어야 한다.
- 순수 검증기는 실제 참조, 중복 대표 문항, 섹션 조건, 주장 근거를 검사한다. 정량 서술(배점·비율·개수·실측)은 코드 표시 영역으로 제한하고 AI 산문에서 감지하면 거절한다. 일반적인 숫자 허용 집합만으로 잘못된 숫자-의미 결합을 허용하지 않는다. 등급컷·예측·적중·전국 기준·학습자 실력 단정·근거 없는 출처/변형/채점·없는 듣기/서술형 언급·HTML·내부 enum/모델명 등도 검사한다.
- 영어 원문 인용은 v1에서 AI가 새로 만들지 않는다. 필요한 경우 기록된 짧은 표현만 코드가 표시하며 전체 최대 3개, 각 20단어 이하로 제한한다. 인용은 `lang=en` 영역에서 수식/enum 치환 없이 표시한다. 모범답안 전문을 공유 보고서에 옮기지 않는다.
- 본 생성 1회, 검증 실패 시 오류와 초안으로 보완 1회까지만. 잘림은 부분 복구하지 않는다. 장문 1,800~3,200자를 목표로 하되 작은 시험/구조 보고서는 근거량에 맞춰 줄인다. 실패는 `status: failed`, 유효한 영어 계약을 통과해야 `completed`다. API의 기존 배열 계약은 유지하고 클라이언트가 해당 항목 상태를 검사한다.

### 저장·동시성·자동 생성

- 공유 순수 서명 함수는 입력으로 사용하는 모든 필드(시험 식별/범위/회차, analysisId, 문항 번호·형식·배점·난도·topic·유형·능력·정규화 영어 근거·ai_comment·어휘/구문, 총점/summary completeness, 학교 통계, 버전)를 포함한다. `ai_comment`도 실제 입력이므로 제외하지 않는다. 키 순서를 정규화하며 서버/클라이언트가 같은 함수를 사용한다.
- 같은 분석의 진행 중 생성은 DB의 기존 extension 행을 이용한 요청 토큰/CAS로 한 건만 허용한다. 새 모델/테이블 없이 구현한다. 두 번째 요청은 충돌 상태로 실패하며 추가 AI 호출을 하지 않는다. 만료된 실행은 제한된 lease 후 재시도 가능하다. 완료 저장 직전 현재 입력 서명과 소유 토큰을 다시 확인한다. 교정·재분석·더 새 요청이 생기면 옛 실행은 저장하지 않는다.
- 실패 시 이전 성공 보고서는 그대로 보존하고 사용자용 오류와 시도 시각만 갱신한다. 첫 실패의 빈 행은 완료 배지로 보이지 않는다. 최근 실패 배너와 입력 변경 배너를 구분한다. 수학에도 응답 `status` 토스트 판정 및 잘못된 완료 배지를 수정하되 프롬프트/저장 동작은 바꾸지 않는다.
- 영어 재분석의 cascade 삭제로 보고서가 사라지는 문제는 직전 유효 영어 보고서를 새 분석으로 이관하여 해결한다. 새 analysisId 서명과 다르므로 이전 근거 배너가 표시된다. 새 분석 실패 시 기존 보고서 보존도 확인한다. 교정은 자동 생성하지 않는다.
- 영어 자동 총평은 사용자가 기존 자동 옵션을 켠 경우에만 실행한다. `hadCommentary`만으로 생성 비용을 추가하지 않는다. 단계는 학습 대책 준비→선택적 총평으로 직렬 실행하고, 학습 대책 실패가 총평을 막지는 않는다. 중복 클릭 및 해당 단계 중 수동 실행을 막는다. 영어에는 metadata 요청이 없다. 수학의 기존 자동 체인은 그대로다.
- 일반 교사도 서버 플랜/데모 권한에 따라 생성한다. 이번 변경의 검증을 끝낸 상태로 함께 제공하며 잠금 해제만 따로 먼저 배포하지 않는다. 사용자 평가를 강제 승인 단계로 새로 만들지 않는다.

### 화면 디자인과 공유

수학 총평과 같은 보고서 품질을 원한다는 요청에 맞춰 V3 테마·서체·이미지 캡처 기술을 재사용한다. 영어 본문은 독립 `EnglishCommentarySection`/`EnglishCommentaryView`로 그린다. 수학 블록 레지스트리/프롬프트/프리셋을 영어 때문에 변경하지 않는다. 기존 영어 V3 산출물은 구형 안내로 읽고 재생성한다. 비활성 HTML/V4 복사 기능은 확장하지 않는다.

디자인 토큰: 기존 브랜드 테마의 종이 `#FFFFFF`, 본문 `#1E293B`, 제목 `#0F172A`, 보조 본문 `#475569`, 강조 `#135BEC`, 구분선 `#D8E0EC`를 기준으로 하되 구현은 `--v3-*` 토큰만 사용한다. 한글 제목은 기존 명조, 본문은 앱 고딕, 영어는 별도 `lang=en` 처리. 테마 선택/저장은 기존 설정 경로를 사용한다. 다크 테마도 본문/배경 토큰의 짝을 지킨다.

```text
[학교 · 학년 · 시험 범위 / 근거 범위]
시험을 구체적으로 설명하는 제목
덱 — 이번 시험에서 확인할 핵심 요구
────────────────────────────────────
시험 구성 [형식] [세부유형] [확인된 출처]
핵심 특징: 해설 문단 + 참조 문항
대표 문항: 번호/유형/배점 | 요구 해설
                           | 기록된 함정·조건
                           | 연결된 연습과 점검
조건이 있는 서답형의 조건·채점 출처
우선 학습 행동과 확인 방법
학부모 결론 / 분석 근거의 범위
```

디자인 검토: 일반적인 KPI 카드 네 개와 '킬러' 숫자 중심 초안을 버렸다. 영어 시험의 판단 요구와 조건을 나란히 읽는 문항 해설을 중심 요소로 삼는다. 본문은 왼쪽 정렬, 한 줄 약 60~75자, 과도한 카드/장식/자동 애니메이션 없이 문단·표·여백으로 위계를 만든다. 캡처 720px와 독립 보고서 375px에서 줄바꿈을 확인한다. 앱 전체의 좁은 화면 지원 범위를 확대하는 일은 이 작업에 넣지 않는다.

### 검증과 역할

1. 순수 테스트: 일반/구조 중심/미확인 출처/객관식만/듣기/영작·소문항/구형·손상 JSON, 허위 참조/수치/채점/원문/출처/조건부 영역, 배점 불일치, 서명 변경, 잘림·복구 제한.
2. 저장 통합 테스트: 실패 후 이전 보고서 보존, 동시에 1건만 실행, 교정 중 생성 거절, 재분석 이관, 플랜/테넌트 권한, 캐시 버전 및 서명. 저장소의 별도 테스트용 레코드 또는 의존성 주입으로 검증하고 사용자 데이터는 수정하지 않는다.
3. 브라우저: 일반 교사 생성→재조회, 실패 토스트/배너, 교정→이전 근거 안내, 재생성→해제, 자동 옵션과 단계 전환, 이미지 블록 수/요약·내용 일치, 720/375px·다크 테마. 실제 AI 호출과 API를 모킹한 브라우저 검증은 구분해 기록한다.
4. 실제 생성: 출처·근거 특성이 다른 6개 명시적 검증 fixture로 실제 모델 생성 및 검증을 수행한다. 실제 시험 데이터가 확보되면 익명화 샘플도 확인하되 fixture를 실제 학교 시험으로 부르지 않는다. 최소 2개의 풍부한 근거 사례는 반복 생성하여 편차도 확인한다. 소문항/배점 미완성 fixture는 생성 차단을 기대한다. 모델 지연·보완 횟수·결과 품질을 기록한다. 평가 축은 근거 정확성/시험 구체성/행동 실행성/학부모 가독성/과장 없음이며 작업자 3자의 실제 출력 검토로 부족한 점을 고친다. 운영자 평가는 후속 선택 사항이다.
5. 수학 `commentary-agent.ts` 변경 없음 및 프롬프트 바이트 동일성, 기존 영어/근거/claims/render/capture/template/contrast 검증 중 관련 범위, TypeScript 검사를 통과한다.
6. 합의 후 역할: Codex는 사용자에게 요청받은 구현 책임자로 UI·연동·통합 검증·최종 수정을 담당한다. Claude는 한정된 영어 백엔드와 검증 모듈을 맡을 수 있고, Grok은 독립 검증/출력 리뷰를 맡을 수 있다. 소유 파일을 분명히 나눠 서로의 변경을 되돌리지 않는다.

### 1차 의견 중 조정한 항목과 이유

- Claude의 V3 프로젝션 대신 Grok의 영어 단일 계약을 선택했다. 수학 슬롯을 채우는 오염을 줄이고 공유 품질은 스타일·캡처 공용화로 얻는다.
- Claude의 근거 50% 미만 차단 대신 구조 보고서를 허용했다. 기본 분석은 완전해야 하지만 세부 근거가 없다는 사실과 문항 누락은 다르다.
- Claude의 같은 학교 비교도 v1에서는 보류한다. 범위 동등성 없는 비교를 없애 구현·검증 범위를 명확히 한다.
- Grok의 학습 대책 병렬 실행 대신 직렬 단계를 선택했다. 기존 화면 상태를 보존하며 학습 대책 자체는 총평 입력이 아니다.
- Claude의 현재 문항 숫자 재투사 대신 생성 시점 스냅샷을 선택했다. 공유 이미지에서 옛 산문과 새 사실이 섞이는 오류를 방지한다.
- 강제 사용자 채점/승인을 완료 조건으로 두지 않는다. 사용자가 끝까지 진행을 지시했으므로 실제 출력·자동 검증·3자 품질 검토를 완료하고 결과를 제공한다.

2차 판정: Codex 동의. Claude **동의(AGREE), 미해결 차단 없음**. Grok **동의(agree), 미해결 차단 없음**. 각 검토 문서의 Round 2에 독립적인 근거와 의견 조정 기록이 있다. 실제 두 에이전트의 완료 보고를 확인한 뒤 구현에 착수했다.

## 실제 출력 검토 후 계약 조정

여러 문항을 연결한 문단에서 일부 문항의 일반적인 단원·형식 설명이 다른 문항으로 번지는 문제가 남았다. 구체 문법·어휘·함정을 각 참조와 대조하는 검사만으로 모든 일반 범주 표현을 열거할 수는 없다. v1의 새 생성은 **핵심 특징과 학습 행동마다 근거 문항을 정확히 하나씩** 연결한다. 특징들은 서로 다른 문항을 골라 형식·요구를 고르게 설명하고, 전체 경향은 개요 및 코드 집계표에서 보여 준다. 저장 스키마와 기존 성공 문서의 읽기는 유지한다.

Codex와 Claude는 이 조정에 동의했다. Grok은 기록이 완전히 같은 문항만 묶는 대안을 권하면서, 단일 참조 고정도 출시 제약으로 받아들인다고 명시했다. Codex는 구현과 근거 해석이 더 단순한 단일 참조를 선택했다. 해당 의견은 실제 Grok 검토 기록에 근거하며, 최종 출력 합격과는 별개다.

최종 조정 판정: Grok도 단일 참조·전체 개요/표·작성 조건에 명시된 필수 표현이라는 세 항목에 **명시적 동의**를 보냈다. 단일 참조가 아닌 기존 성공 문서의 읽기는 유지하며, 제한은 새 생성의 검증에 적용한다.

추가로 핵심 어휘·구문 기록을 답안 필수 제시어로 추론하지 않는다. 필수 사용 조건은 작성 조건에 해당 표현이 명시된 경우만 설명한다. 대비 방법으로 제안하는 연습과 시험에서 실제 요구하는 답안 조건은 구분한다. 수정 후 전체 6개 사례와 2개 반복을 새로 생성하여 재검토한다.
